# REMAKE Frontend — Agent Guide

Rules for AI coding agents (Claude Code, Codex, etc.) working in `frontend/`. Follow them together with the root `AGENTS.md`.

Korean translation for developers: [`docs/developer/frontend-agent-guide.md`](../docs/developer/frontend-agent-guide.md)

## Read first

- Before starting, read [blueprint.md](./blueprint.md) for the tech stack, folder structure, routes, and data flow.
- If you need a structure or library that differs from blueprint.md, ask a human before changing code.

## Required rules

- Use **pnpm** only. Do not use `npm`, `yarn`, or `npx` (use `pnpm dlx`, `pnpm exec`).
- Run commands from `frontend/`. The git root is one level up (`REMAKE/`).
- **No Tailwind.** Write styles only with CSS Modules (`*.module.css`) and the CSS variables (design tokens) in `app/globals.css`. Do not add Tailwind, shadcn/ui, styled-components, emotion, or other styling libraries.
- Handle server data only with TanStack Query. Keep Zustand for minimal client state such as login info.
- Call APIs through `lib/api/client.ts` (openapi-fetch). `lib/api/schema.d.ts` is generated by `pnpm gen:api`; never edit it by hand.
- Do not reimplement backend features as Next Route Handlers or Server Actions. Business logic belongs to the Spring backend.
- Never create a route whose URL starts with `/api/`, including through route groups such as `app/(group)/api/`. In production the proxy sends every `/api/` request to the backend (blueprint.md §1).
- Call the API from Client Components. If a Server Component needs to call the backend, ask a human first; it needs a separate server-side address (blueprint.md §5).
- Read environment variables only in `lib/env.ts`. When adding a variable, also add it to `.env.example`.
- Use Solar icons only (`@solar-icons/react/<style>`). Do not add lucide or any other icon library.
- For dates, use the `dayjs` exported from `lib/dayjs.ts` (ko locale configured).
- Build forms with React Hook Form + Zod (`@hookform/resolvers/zod`).
- If a backend API does not exist yet, add an MSW handler in `mocks/handlers.ts` and develop against it.
- Follow the UI rules from the product policy (blueprint.md §10). AI inputs are selections only: never add a free-text box for recipe or meal-plan generation. Show the expiry `status` and `dDay` the server returns; do not recompute them.
- Send analytics events only through the shared tracker (blueprint.md §11). Never put personal data or free text in event properties.

## Where code goes (colocation)

Full rules: `blueprint.md` §3.1.

- Colocate: code used by one route lives in that route folder's private folders `_components/`, `_hooks/`, `_lib/` (`queries.ts`, `schema.ts`, `utils.ts`). Keep `page.tsx` thin.
- One folder per component: `.tsx` + `.module.css` + any hook/util only that component uses.
- A route may import colocated code from its own folder and ancestor route folders only — never from sibling or unrelated routes.
- When two unrelated routes need the same code, promote it: UI → `components/<Name>/`, React hook → `hooks/`, query keys/hooks → `lib/queries/<domain>.ts`, other functions → `lib/`. Shared code must not know about a specific page.
- Import colocated code with relative paths and shared code with the `@/` alias (`@/*` → `./*`). Never import from `@/app/...`.

## After changes

All of these must pass after a change:

```bash
pnpm lint
pnpm typecheck
pnpm build
```

- ESLint rules live in `eslint.config.mjs` (import sorting, type imports, no direct `dayjs` / `process.env`, no imports from `@/app/...`, etc.). Use an `eslint-disable` comment only together with a stated reason.
- Prettier handles formatting. Husky + lint-staged run automatically on commit. Never skip the hook with `--no-verify`.
- Branches, commits, and PRs follow the Git convention in the root `AGENTS.md` (commit types: `feat`, `fix`, `chore`, `docs` only; every commit has a body).
