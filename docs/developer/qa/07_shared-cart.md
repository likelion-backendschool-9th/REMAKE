## CART. 장바구니 (최유리)

화면 코드: `cart_list`(p7 장바구니: 일반·삭제 모드·수량 변경 시트·빈 화면).
API: 45 목록, 46 수량 변경, 47 냉장고로 옮기기, 48 선택 삭제. 담기는 API가 아니라 UseCase(`AddCartItemsUseCase`)로만 일어난다(식단표 생성 · 내 레시피 저장 · 공유 레시피 저장). 영수증 선택 차감은 `DeductCartItemsUseCase`(RCP-41~48).
**구현 상태(2026-11-24 기준)**: 차감 UseCase와 저장 기반(#219), 목록·수량 변경·삭제·냉장고 이동 API(45~48)와 공통 담기 UseCase(#226)가 들어왔다. 레시피·식단표 쪽에서 담기 UseCase를 부르는 연결과 화면(#216은 마크업만) 연동은 별도라, 담기 시나리오는 호출 연결을 확인한 뒤 실행한다.
v3에서 사라진 것: 직접 담기, 레시피 묶음(`group_name`)·`meal_plan_id`, 이름만으로 자동 삭제, 재저장 시 수량 덮어쓰기, 외부 쇼핑몰 이동·결제.
식단에서 레시피가 빠질 때(칸 삭제·교체·덮어쓰기)의 장바구니 정리는 #91에서 정했다(2026-11-26 기획 확인, CART-10, MEAL-33·52).

## SHARE. 공유 공간·랭킹 (최유리)

화면 코드: `recipe_ranking`(p4.1.4 이번 주 레시피 랭킹), `shared_write`(p4.1.1.1 공유 작성), `shared_detail`(p4.1.4.1), `shared_report`(신고 시트). 레시피 탭의 "금주의 레시피" TOP 3 카드는 `recipe_home`.
API: 49 TOP 3, 50 랭킹, 51 공유, 52 공유 상세, 53·54 저장·취소, 55 신고, 사진 조회(`GET /user/shared-recipe-photos/{id}`). 정기 작업: 매주 월요일 0시 순위 기록·보상.
**구현 상태(2026-11-24 기준)**: 51(공유·사진 저장), 52(상세), 55(신고), 사진 조회가 구현됨(#86, #214, #64). 49·50(TOP 3·랭킹), 53·54(공유 저장·취소), 주간 순위 기록·보상 작업과 `generation_quota_grants`는 구현 전이라 **막힘**으로 시작한다.
v3에서 사라진 것: 닉네임·작성자 표시, 사진 여러 장, 공유 확인 모달, 공유 저장 사본, `shared_recipe_saved` 이벤트, 신고 자동 숨김, 레시피 묶음 표시.

### 작성자 삭제 구현 상태 (#230 확정 / #296 BE 구현)

위 2026-11-24 메모는 당시 이력이에요. 현재 TOP 3·랭킹·저장/취소·주간 확정과 #296의 본인 목록·삭제 API·canDelete·DELETED·사진 정리 큐를 구현했어요. 본인 목록 필드는 id/title/imageUrl/status/sharedAt/canDelete, 공유 시각·ID 내림차순이며 page>=0·size=1~100(기본 20)이에요. 본인 반복 삭제는 204, 타인/미존재는 404, 잘못된 입력은 400이에요. HIDDEN 상세는 작성자만 읽고 imageUrl은 null이며 사진 직접 접근은 모두 404예요. SHARE-DEL의 BE 회귀는 `SharedRecipeDeletionApiTest`로 검증하며 디자인/FE(#298/#299)와 삭제/주간 확정 경합(#297)은 여전히 후속이에요.
