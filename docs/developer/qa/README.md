# QA 시나리오 (이슈 #191)

기능이 정의서대로 동작하는지 확인할 시나리오 모음입니다. QA를 하는 사람은 이 표를 하나씩 실행하고 결과를 남기고, 구현하는 사람은 자기 영역 시나리오를 완료 기준으로 봅니다. 구현 가이드는 [`../guide/`](../guide/README.md)에 있습니다.

기준 문서는 PRD v4·정책정의서 v4·ERD v4·API 정의서 v4·에러 정의서 v2·이벤트 정의서 v2(피그마 기준, 2026-11-22)이고, 저장소에서는 [`docs/agent/spec/`](../../agent/spec/)과 [`docs/developer/guide/`](../guide/README.md)를 봅니다. 한글만 있고 영문판은 없습니다.

시나리오를 작성한 것과 테스트를 통과한 것은 다릅니다. 이 문서의 모든 시나리오는 아직 **미실행**입니다(`결과` 칸이 비어 있으면 미실행). 각 영역 맨 위의 "구현 상태"는 작성 시점(2026-11-24)의 기록이므로 최신 상태는 연결된 이슈를 확인합니다.

## 읽는 법

| 칸 | 뜻 |
| --- | --- |
| ID | 영역 약어 + 번호. 영역: AUTH(시작하기·설정·계정), ING(냉장고), RCP(영수증), EXP(월 식비·소비 패턴), AI(AI 레시피), MEAL(식단표), NOTI(알림), CART(장바구니), SHARE(공유·랭킹), SUB(구독), COM(공통) |
| 화면·API | 화면 코드(이벤트의 `screen` 값)와 API 번호. 화면 코드는 41개이고 URL 수와 같지 않다 |
| 전제 | 로그인한 일반 사용자 외에 필요한 준비. 비어 있으면 로그인한 일반 사용자 1명 |
| 행동·입력 | 사용자가 하는 행동과 넣는 값 |
| 기대 결과 | 화면·응답·DB·이벤트에서 확인할 것 |
| 방법 | A=API(Postman·MockMvc), E=화면 E2E·수동, M=실기기, D=DB 확인, B=배치·스케줄러, V=이벤트 적재 확인 |
| 근거 | **확정**=정의서대로 검증, **제안**=팀 확정 전이라 기대 결과가 바뀔 수 있음, **미결**=기대 결과를 정할 수 없어 결정 이슈에 연결, **대기**=규칙은 정해졌고 화면이 아직 없음, **확인**=구현에서 문제 가능성이 있어 결과를 봐야 함 |
| 우선 | P0 먼저 돌림 |
| 연결 | 구현 이슈·결정 이슈·이벤트 번호 |
| 결과 | 실행한 뒤에만 채운다(양식은 아래) |

미확정 정책은 기대 결과를 임의로 정하지 않고 결정 이슈에 연결한다. 남의 리소스 접근은 존재 여부를 알리지 않으려고 **404로 통일**한다.

### 결과 기록 양식 (실기기·통합·이벤트 검증이 같이 쓴다)

실행할 때마다 시나리오 ID별로 한 줄씩 남긴다.

| 칸 | 내용 |
| --- | --- |
| 시나리오 ID | 예: ING-24 |
| 실행일·실행자 | |
| 서버 버전 | 배포된 커밋 해시(`dev` 기준 7자리) |
| 클라이언트 | 프론트 빌드 버전, 브라우저·OS·기기(실기기면 모델) |
| 환경·목 여부 | 개발/로컬, OCR·AI·결제 등 외부 연동을 목으로 썼는지 |
| 결과 | 통과 / 실패 / 막힘(선행 미구현) / 미실행 |
| 증거 | 실패면 `traceId`, 요청·응답, 스크린샷 |
| 기대 / 실제 | 실패한 경우만 |
| 결함 이슈 | 해당 기능 담당 이슈에 연결 |
| 이벤트 확인 | 발행 이벤트 이름·속성·1회 적재 여부(V) |

## 테스트 준비물

| 준비물 | 내용 |
| --- | --- |
| 계정 | 일반 사용자 2명(A, B: 소유권 테스트용), 온보딩을 건너뛴 신규 계정 1개. 어드민 화면은 보류라 ADMIN 계정은 필요 없다 |
| 재료 데이터 | 소비기한이 오늘·내일·3일 뒤·4일 뒤·어제인 재료, 단위가 g·ml·개·팩인 재료, 가격 있음·없음 |
| 날짜 | 서버·화면 시간을 바꿀 방법(자정·월 경계). 백엔드 통합 테스트는 `clock.advance` |
| 사전 데이터 | `ingredient_catalog`(대파·우유 등)가 들어 있어야 단위 결정을 확인할 수 있다 |
| 이벤트 확인 | `events` 테이블 조회 권한 |
